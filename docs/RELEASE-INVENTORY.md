# Release inventory

What a release of Uptime Orchestrator consists of, where each artefact comes
from, how it is verified, and under which licence it travels. The source
repositories are `uptime-lab/orchestrator` (server, agent, protocol, signer),
`uptime-lab/orchestrator-agent` (a read-only source mirror of the agent, one
commit per agent release) and `uptime-lab/orchestrator-boot-image` (the
recovery image).

## Versioning

- Agent releases are tagged `agent-v<semver>` on the mirror, one commit per
  release. The agent's module path is the bare `agent` and `proto/` has no
  `go.mod`, so `go get` cannot resolve it from any host; build from a clone
  (`cd agent && go build ./...`) instead until the module paths are canonical.
  The Go-valid `agent/v<semver>` tag is added only
  from that point on: before it, the tag would name nothing a Go tool can
  fetch. The server
  refuses an agent below its floor (`domain/node_command.MinAgentVersion`),
  and the agent refuses to downgrade below its own anti-rollback floor.
- Platform releases are tagged `platform-v<semver>`; the three images of one
  tag are built from one commit and are meant to be deployed together. Once
  all three exist, the release workflow creates the tag's GitHub Release (no
  assets; a pre-release for a release candidate, marked latest only for the
  highest final version), which is where the installer finds its default
  version; the installer falls back to the newest final tag.
- The recovery image is versioned by the agent it carries and by the
  Buildroot base it was built from; the base id is what the source offer
  names.
- The installer, `tools/install/install.sh`, belongs to the platform release
  it is tagged with: it installs that release's compose file and images,
  and the recovery image that release's `recovery-image.env` names.

## What is NOT part of a release

- The instance-admin console, the deployment compose files, the reverse-proxy
  configuration and the operations scripts of the hosted service: they live
  in a private operations repository and are not distributed.
- Any credential, signing key or entitlement signing key.
